# Study Helper 智能学习助手 - 开发实施计划书 (MVP 阶段)

## 1. 项目概述
*   **产品定位：** 专注于辅助中小学生学习的 AI 智能体应用，提供苏格拉底式的答疑、个性化薄弱点强化及日常练习。
*   **产品形态：** 跨端应用（前期 H5 Web 端跑通全链路，中期上线微信小程序，后期打包 App）。
*   **核心策略：** “重 AI 编排，轻本地数据”。前期不自建庞大题库，利用大模型泛化能力和向量库检索历史数据。

## 2. 技术栈选型
| 模块 | 技术选型 | 备注说明 |
| :--- | :--- | :--- |
| **前端架构** | Uni-app (Vue 3) / Taro (React) | 跨端框架，一套代码编译 H5 和微信小程序 |
| **公式与渲染** | `markdown-it` + `KaTeX` / `MathJax` | 核心难点：解析大模型返回的 LaTeX 数学公式 |
| **AI 编排层** | Dify (Docker 开源自部署) | 将 AI Prompt、打标、工作流可视化编排并暴露 API |
| **业务后端** | Python (FastAPI) | 承担用户鉴权、数据持久化、请求中转分发 |
| **数据库** | PostgreSQL + `pgvector` 扩展 | 关系型数据存用户/记录，向量存储用于相似题检索 |
| **底层大模型** | Qwen-VL-Max / Claude 3.5 / GPT-4o | 视觉多模态能力强，作为 OCR 和核心解题大脑 |

## 3. 核心业务数据流转设计

### 3.1 核心答疑链路 (拍照 -> 解析 -> 反馈)
1.  **用户**通过前端拍照/传图上传。
2.  **FastAPI** 接收图片，转存至 OSS（对象存储），提取 URL 发送给 **Dify API**。
3.  **Dify Workflow** 执行：
    *   *节点 A (多模态识别)：* 识别学科、提取题干文本。
    *   *节点 B (知识点提取)：* 输出该题目的二级知识点标签（如：初中数学-勾股定理）。
    *   *节点 C (苏格拉底解答)：* 严格限制**不直接给最终答案**，先给出解题思路和第一步。
4.  **前端**通过 SSE（Server-Sent Events）接收流式输出，实时渲染 Markdown 和 LaTeX 公式。
5.  **用户**点击反馈按钮：
    *   **`<我不甚理解>`**：发送特定指令，Dify 进入“分步拆解”分支，输出更细致的下一步。
    *   **`<我会了>`**：Dify 进入“总结”分支，并触发生成一道“相似题”的指令。

### 3.2 几何图形渲染方案
*   **AI 侧：** Prompt 约束大模型在遇到几何题时，除了文字解析，必须在代码块中输出一段标准的 `SVG` 代码（包含线条、顶点字母）。
*   **前端侧：** 正则匹配到 XML/SVG 代码块后，不作为普通代码块显示，而是直接通过 `<image>` 或 DOM 渲染为矢量图形。

## 4. 实施路径 (Action Plan)

计划分为 4 个 Sprint (迭代周期)，预计耗时 4-6 周。

### Sprint 1: AI 引擎与基础设施搭建 (1周)
*   [ ] **任务 1.1**：购买云服务器（2C4G或以上），安装 Docker。
*   [ ] **任务 1.2**：部署开源版 Dify。
*   [ ] **任务 1.3**：在各大平台（阿里百炼、智谱、OpenAI 等）申请 API Key，并在 Dify 中配置模型凭证。
*   [ ] **任务 1.4 (核心)**：在 Dify 中建立一个 Chatflow（工作流），编写并调试多模态解题的 System Prompt，确保遇到图文题目能返回带标准 LaTeX 格式的解析，并在最后返回结构化的 JSON（包含学科分类、知识点标签）。

### Sprint 2: 业务后端与数据库搭建 (1周)
*   [ ] **任务 2.1**：搭建 FastAPI 基础工程（路由、鉴权中间件、日志记录）。
*   [ ] **任务 2.2**：设计 PostgreSQL 数据库表结构：
    *   `users` (用户信息)
    *   `chat_sessions` (对话会话)
    *   `chat_messages` (聊天记录，存 Dify 的 Message ID)
    *   `user_tags_history` (用户知识点打标记录，关联错题/薄弱点)
*   [ ] **任务 2.3**：对接 Dify API，使用 FastAPI 包装一套对前端友好的流式接口 `/api/v1/chat/completions`。
*   [ ] **任务 2.4**：实现**知识点打标逻辑**，在每次对话结束后，后端提取 Dify 识别的“知识点”，写入数据库更新用户的“薄弱点热力值”。

### Sprint 3: 跨端前端搭建与重难点攻坚 (1.5周)
*   [ ] **任务 3.1**：初始化 Uni-app / Taro 项目，搭建基础 UI 框架（首页、聊天对话页、历史记录页）。
*   [ ] **任务 3.2 (难点)**：实现类似 ChatGPT 的打字机效果（对接后端流式 API）。
*   [ ] **任务 3.3 (难点)**：引入并封装 `markdown-it` 和公式解析插件。测试极端的嵌套数学公式和复杂的化学方程式，确保页面不崩溃、排版不乱。
*   [ ] **任务 3.4**：实现相册选图/拍照上传功能（注意图片压缩，避免传给大模型的图片过大导致响应慢）。
*   [ ] **任务 3.5**：渲染 AI 生成的 SVG 几何图形。

### Sprint 4: 业务闭环、演练与多端打包 (1.5周)
*   [ ] **任务 4.1**：前端实现 `<我会了>` / `<不甚理解>` 悬浮按钮及相应的交互逻辑。
*   [ ] **任务 4.2**：实现“生成相似题”功能（调用大模型 Prompt，基于当前题干替换情境和数据重新生成）。
*   [ ] **任务 4.3**：完成“个人数据库（历史记录/错题本）”的前后端联调，展示用户各学科的薄弱知识点雷达图。
*   [ ] **任务 4.4**：实现“日常练习”模块（H5 页面上选择年级，调用大模型生成当天的 5 个单词或 1 句古诗）。
*   [ ] **任务 4.5**：H5 兼容性测试，并在微信开发者工具中打包预览微信小程序，处理微信特定的网络白名单和权限校验。

## 5. 前期开发核心避坑指南 (Tips)

1.  **公式渲染的坑：** 大模型吐出的公式格式经常不统一（有时候用 `$...$`，有时候用 `\[...\]`，有时候转义符会丢失如 `\\n`）。**对策：** 必须在 Dify 的 Prompt 中极其严格地要求它使用标准且唯一的数学公式边界符（推荐块级公式用 `$$...$$`，行内用 `\(...\)`），并在前端做正则预处理清洗。
2.  **大模型算力幻觉：** 纯文本大模型做初高中数学计算题很容易在最后一步算错。**对策：** 尽量选用带有强大推理能力或内置 Code Interpreter 的模型（如 Qwen-Max, DeepSeek-Coder），并在 Prompt 中加上 *“请一步一步思考，并在给出最终答案前复核你的计算过程”* (CoT 思维链)。
3.  **响应耗时：** 多模态图片解析通常较慢（可能长达 3-8 秒首字返回）。**对策：** 前端必须做足 Loading 动画，上传图片后立即在聊天框展示出图片预览和进度条，缓解用户等待焦虑。
